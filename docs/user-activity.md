# 用户使用统计

仅机器人管理员可在私聊使用：

- `/stats`：累计用户数、今日活跃用户数、近 7 天活跃用户数。
- `/users` 或 `/users 2`：按最近使用时间倒序分页，每页 8 人；支持上一页、下一页和刷新。
- 管理员 `/help` 中提供命令说明。群聊不返回用户数据，翻页回调同样重新验证管理员身份。
- 管理员私聊的 Telegram 命令菜单和输入补全中提供 `/stats`、`/users`，保留原有公共命令；普通用户和群聊菜单不增加这两个入口。启动时注册，`/reload` 时更新并清除本次撤销管理员的专用菜单；手机端如未刷新，可退出聊天后重新进入。

## 统计口径

统计从功能上线后开始，不从已有设置、歌曲缓存或日志补录历史。
仅统计非机器人管理员：使用现有 `BotAdmin` 名单，管理员的所有操作均不写入活动记录；查询总人数、活跃人数和分页列表时，也排除当前管理员的既有记录。
无需额外开关，`/reload` 更新管理员名单后，计数与查询同步使用新名单。这里的管理员指机器人管理员，不是普通群管理员。
既有记录不删除。用户成为管理员后，其记录隐藏且暂停计数；撤销管理员后，原记录重新可见并恢复计数，不补计其担任管理员期间的操作。
每位 TG 用户在 `docker-data/data.db` 的 `user_activity` 表中只占一行，保存 ID、当前已知用户名和显示名、首次和最近使用时间、累计交互次数。
不保存消息正文、群聊明细或每次交互记录。清理歌曲缓存和重启不会清空用户统计。

计数发生在路由已接收、进入处理的请求上，包括命令、私聊搜索、支持的歌曲链接、听歌识曲媒体、按钮操作、非空内联搜索、选中内联结果及访客请求。
计数表示请求次数，不表示成功下载次数。内联搜索输入变化可能产生多个请求。管理员查询统计、刷新或翻页不会改变统计结果、交互次数及最近使用时间。
机器人用户、自动转发、匿名频道身份、自己的内联回显、普通未匹配群消息和未通过白名单的请求不计入。
处理函数内部调用其他处理函数不会重复计数。

重复投递通过进程内有界缓存去重（24 小时、最多 16384 个键），不额外保存永久事件日志；重启或缓存淘汰后的重复投递不保证精确去重。
数据库更新采用原子累加，保留并发、乱序请求中的最早及最近时间。统计写入失败不会中断歌曲处理。

时间统一存为 UTC，查询按机器人运行时区显示（当前 Compose 的 `TZ=Asia/Shanghai`）。
今日活跃指当天零点起使用过的不同用户，近 7 天指今天及前 6 个日历日。

实现集中在 `bot/user_activity.go`、`bot/db/user_activity.go` 和 `bot/telegram/handler/user_activity_*.go`，只在数据库初始化、应用注册和路由分发处接入；不扩展核心 `SongRepository` 接口或修改平台解析代码。
