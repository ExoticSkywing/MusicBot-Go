# 手动更新广播

广播不会随更新、启动、重启或 `/reload` 自动发送，也不会自动生成公告。
仅 `BotAdmin` 管理员在私聊中可用，管理员命令菜单和帮助中提供 `/broadcast`。

## 使用

管理员在与机器人的私聊中发送，例如：

```text
/broadcast 更新通知

本次已修复部分歌曲下载失败的问题，可以正常使用了。
```

1. 机器人显示预计人数、完整正文和「确认发送 / 取消预览」按钮，此时没有群发。
2. 确认后只发送公告正文，不附带管理员操作按钮、预览标题或人数。
3. 发送期间可点击「停止发送」，或发送 `/broadcast cancel` 停止自己的广播。
4. 完成后原预览消息显示成功、失败或结果未确认、跳过及未处理人数。

支持多行纯文本，不解析 Markdown/HTML，不发送图片或附件，不展开链接预览。
正文最多 3000 个 UTF-16 单元（部分 emoji 占 2 个），为各语言的预览提示预留空间。
沿用管理员命令的敏感值脱敏，实际发送与预览正文一致；不要在公告中放 Cookie 或令牌。

每位管理员仅保留一个待确认预览，10 分钟过期；新预览替换自己的旧预览。
确认绑定发起人、私聊、预览消息 ID 和随机令牌，重复点击不会重复启动。
整个机器人同时只运行一个广播；确认时固定使用预览名单，不额外加入后来出现的用户。
已送达消息不会因取消而撤回；取消时已在途的请求仍可能送达。
重启会丢弃待确认预览和进行中的任务，绝不自动续发。

## 接收对象与通知开关

- 仅记录收到的真实私聊消息或私聊按钮交互；不从 `/users`、用户设置、群聊、内联请求推断可私信状态。
- 旧版本未保存可靠私聊名单，因此从功能上线后开始记录；老用户再次私聊后加入，不要求重新 `/start`。
- 排除当前机器人管理员、关闭通知的用户、已确认不可达的用户及白名单不允许的用户。
- 用户可在私聊 `/settings` 中切换「📣 接收更新通知」，默认开启，不影响搜歌和下载。群设置不显示此项。
- 发送前再次检查权限、白名单和通知开关，预览后退出通知的用户也会被跳过。
- Telegram 返回已屏蔽、账号停用或聊天不存在时标记不可达，下次跳过；用户再次私聊后恢复可达标记，但不会覆盖手动关闭通知的选择。

## 发送与存储

以最多每秒 5 人串行发送，并复用现有 Telegram 发送限流队列及 `retry_after` 重试。
限流重试耗尽、账号鉴权失败、管理员权限被撤销或名单读取失败时停止剩余任务。
普通网络错误不自动重发，因其可能已被 Telegram 接收，统计为「失败或结果未确认」。
不使用付费广播接口。

`data.db` 中独立的 `broadcast_recipients` 表每个用户仅存 ID 和不可达标记；
通知开关复用 `plugin_settings`。清理歌曲缓存不会删除这些记录。
公告、预览和发送名单只存在内存，不建立正文历史或逐次投递明细表。
日志只记录汇总数量和技术错误，不记录公告正文或名单。

## 上游同步边界

实现集中在 `bot/broadcast.go`、`bot/db/broadcast*.go`、
`bot/telegram/handler/broadcast*.go` 和独立的 `broadcast.*.toml` 语言文件。
接入点仅为数据库迁移、应用启动/停止与命令注册、私聊观察中间件、管理员菜单和私聊设置的 `UserOnly` 过滤。
不扩展 `SongRepository`，不改平台解析、下载、缓存、用户统计或上游更新流程。
无需新增容器、依赖包或配置项。

测试使用本地模拟 Telegram 服务；开发验证不向真实用户发送公告。
